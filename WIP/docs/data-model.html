Why the schema looks the way it does — key design decisions

DecisionChoiceRationale
Primary key for UsersUserId (Entra Object ID, GUID)Immutable. UPNs change with name changes, marriages, domain renames; Object IDs never change.
Primary key for MailboxesExchangeGuid (GUID)Immutable in Exchange, populated for every mailbox type. Object IDs are NULL for some shared mailboxes.
Mailbox-to-User linkNullable FK (Mailboxes.UserId → Users.UserId)UserMailbox has a user; SharedMailbox/RoomMailbox/EquipmentMailbox do not.
Deletion handlingSoft-delete (IsDeleted + DeletedAt)Permission history must remain queryable after a user/mailbox is removed.
Index strategyFiltered indexes WHERE IsDeleted = 0The hot-path query "find this active user/mailbox by UPN/Mail" only ever scans active rows.
Token cursorsGeneric DeltaTokens table, one row per sourceWill be reused for groups_delta, mailboxes_delta when added — no schema changes needed.
Sync trackingSyncLog with FunctionName columnSingle table tracks every function execution across the solution; queryable for monitoring.
GrantSource pattern (planned)Direct vs GroupResolved + nullable SourceGroupId FKReporting can show "Bob has access via Finance-DL group" rather than just "Bob has access".
